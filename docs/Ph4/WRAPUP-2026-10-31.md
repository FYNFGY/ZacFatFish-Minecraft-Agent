# Wrap-up / stability round (2026-10-31, after Test A was marked not feasible)

Scope chosen by the user: no new features, close the known defects first. All changes are in the
MCP server / daemon (JavaScript), so they took effect without restarting the game.

## 1. Restart does not lose the world any more

| path | fix |
|---|---|
| `clean-start.ps1` | calls `save_world` through the daemon (`/call`) and waits 2 s before killing |
| `stop-all.ps1` | same save-before-kill block |
| `save_world` tool | new mod tool + MCP tool that sends `/save-all` |

Verified: `clean-start.ps1` printed `save_world: ok=True`, and the player kept the same coordinates
across the restart (`evidence/fix-state3.json`).

## 2. Plant clearing

`WalkToJob.clearable()` now recognises bamboo, sugar cane, cactus, dead bush, mushrooms, lily pads,
dripleaf, azalea, moss, seagrass, kelp, roots, sprouts and lichen; `blockingPlant()` scans the front
cell, feet/head and the four front diagonals; the thresholds dropped to 4 (walk_to) / 6 (path_to)
stuck ticks. Verified with a placed `sweet_berry_bush[age=3]`: `cleared: 1`
(`evidence/fix-walk-bush.json`).

## 3. Boats

- `place_boat` now uses `gameMode.useItem` (water has no collision, `useItemOn` never reaches
  BoatItem), sets `yRotO/xRotO`, sends a rotation packet so the **server** raycasts with the same
  aim, retries 4 pitch variants, and reports the raycast result (`pick`).
- the MCP wrapper now polls `entity_query` for the boat entity after the placement, so it returns a
  real `entityId` instead of -1.
- `boat_sail` / `place_boat` accept the pack's `minecraft:boat` entity type (`isBoatType`).

Verified: placement `SUCCESS` with `pick=water`, boat entity persisted, and `boat_sail` sailed 45
blocks in 6.6 s and dismounted (`evidence/fix-boat13.json`, `fix-boat14.json`, `fix-sail3.json`).

## 4. User abort cancels the job (extends P1-11 to the daemon)

Two layers:
- `notifications/cancelled` / MCP session closing still cancels jobs (Phase 4, `p1-11-abort.json`);
- **daemon watch**: `POST /watch {jobId, ttlMs}` re-armed by `ph4.mjs job()` on every poll. If the
  agent process dies (DSH kills it) the TTL expires and the daemon cancels the job.
  Test: `test/daemon-abort.mjs` - start `walk`, arm the watch, abort the poll, wait 5 s, the job is
  `cancelled` and the daemon log shows `[daemon] watch expired for <id>; cancelling (caller gone)`.
  Evidence: `evidence/daemon-abort.json` (pass).

## 5. Drops above the player

`collect_drops` (MCP wrapper) now: tries the normal collection, and if nothing was collected it reads
the nearest item entity, runs `path_to` to its **exact block** (Baritone can climb) and collects
again. Not yet exercised live - noted below.
