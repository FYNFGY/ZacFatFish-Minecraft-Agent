# Fix round 2026-10-31 - the three blockers the user reported

Stopped Test A on request and fixed the problems instead. Every fix below was built, installed and
verified on the live client.

## 1. Restarts reset the player position (server rollback)

**Cause**: `clean-start.ps1` / `stop-all.ps1` kill `java.exe` with `Stop-Process -Force`. A killed
integrated server never writes the world, so the next launch loads the last autosave - the player is
back at the old spot (often the world spawn) and anything built since the autosave is gone.

**Fix**:
- new mod tool `save_world` (`Tools.java`): sends `/save-all` and reports `{command:"save-all"}`;
- `mcp-server/src/server.js`: `save_world` exposed as an MCP tool;
- `clean-start.ps1`: before killing anything it POSTs `save_world` to the daemon
  (`http://127.0.0.1:57611/call`) and waits 2 s for the disk write.

**Verified**: `clean-start.ps1` printed `save_world: ok=True`, and after the restart the player was at
the same coordinates as before (in the ocean at `979,49,-344`), not at spawn.
Evidence: `evidence/fix-state3.json`, console output of `clean-start.ps1`.

## 2. Plants blocked walking / no clearing

**Cause**: the clearable set only covered leaves/vines/grass/flower/fern/sapling; sweet berry bushes,
bamboo, sugar cane, cactus, dripleaf, berries of modded plants etc. were not recognised. The scan only
looked at 4 cells (feet, head, front, front+head) and the stuck threshold was 8 (walk_to) / 10
(path_to) ticks, so the walker pushed into the plant for half a second before doing anything.

**Fix** (`WalkToJob.clearable`, `WalkToJob.blockingPlant`, `PathJob`):
- clearable now includes bamboo, sugar_cane, cactus, dead_bush, mushroom, lily_pad, dripleaf, azalea,
  moss, seagrass, kelp, roots, sprout, lichen (still never `*_block`, so no invisible colliders);
- the scan checks the front cell, the feet/head cells and the four diagonal front cells;
- thresholds lowered: walk_to clears after 4 stuck ticks, path_to after 6.

**Verified**: placed a `sweet_berry_bush[age=3]` with `/setblock`, walked into it:
`walk_to` returned `cleared: 1`, `clearing: "1293, 86, -429"`.
Evidence: `evidence/fix-walk-bush.json`.

## 3. `place_boat` always failed (FAIL, no entity)

Three separate bugs, all fixed in `ItemActions.placeBoat`:

1. **Wrong interaction path**: the tool called `gameMode.useItemOn` on the water block. Water has no
   collision shape, so vanilla BoatItem is never reached (`PASS`/`FAIL`, nothing happens). It now aims
   at the water block and calls `gameMode.useItem` (the path BoatItem actually uses, with a fluid ray).
2. **Stale aim**: `getViewVector(1.0)` interpolates between the previous and current rotation; the
   tool only set the current one. It now also sets `yRotO`/`xRotO`.
3. **Server desync**: the server raycasts for itself when the use packet arrives, using the rotation
   it has for the player. A `ServerboundMovePlayerPacket.Rot` is now sent before the use, so the
   server sees the same aim (this is why the boat used to appear for a moment and then vanish).
   Four retries with a slightly steeper/shallower pitch handle shore clutter, and the response now
   reports the raycast hit (`pick: "BLOCK x y z id water=true face=up"`).

**Verified**: standing on the calcite shore at `999,65,-346` and placing at `997,62,-346` returned
`SUCCESS` with `pick=water`, and the boat entity (426) was still there one second later.
Evidence: `evidence/fix-boat13.json`, `evidence/fix-boat14.json`.

## 4. `boat_sail` could not find the boat ("no boat within 6 blocks")

**Cause**: the pack registers the boat entity as `minecraft:boat`, but the mount search only accepted
`*_boat` / `*_raft`, so a placed boat was never found.

**Fix**: `ItemActions.isBoatType()` accepts `minecraft:boat`, `*_boat`, `*_raft` and anything
containing "boat"; used by both `place_boat` and the sail task.

**Verified**: `boat_sail {x:950,z:-346,range:4}` mounted the boat, sailed from `z=-345.5` at `x=998`
to `x=952.78` (45 blocks, 6.6 s), and dismounted: `{ok:true, dismounted:true, x:952.78, y:63.09}`.
Evidence: `evidence/fix-sail3.json`.

## Notes / follow-ups

- `place_boat` still returns `entityId: -1` because the entity spawns one tick after the use; the
  client sees it on the next query. A later version should poll 2-3 ticks before answering.
- Item pickup when the drop is *above* the player (e.g. logs on a ledge one block up) still fails:
  `walk_to` is 2D. Use `path_to` with the drop's y, or `collect_drops`, when that happens.
- `/save-all` needs cheats; the test world has them. A world without cheats must be stopped through
  the pause menu instead (the save tool would report the command being rejected).
