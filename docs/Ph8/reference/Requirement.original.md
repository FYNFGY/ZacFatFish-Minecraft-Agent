# Requirement Main
创建一个MCP服务器，包含以下Tool，每个Tool都可以非阻塞运行来保证在低Token ps下能够让大模型较为流畅地控制游戏假人。
MCP服务器的构架允许由若干个模组构成，模组可以加装到服务端，如果有现成的模组能够满足需求，就用现成的，否则就自己开发。
#### 寻路模块
使用Baritone模组
#### 交互逻辑
1. AI玩家可以与游戏内的所有容器交互（箱子，木桶，末影箱等原版物品及各种模组容器），包括拿取物品，放置物品
2. AI玩家能够破坏和放置方块，正常使用原版及模组中工具及武器。
3. AI玩家可以与工作台交互，值得注意的是，AI玩家可以通过JEI物品管理器（整合包自带）来获取物品合成配方
4. AI玩家可以与生物（村民，流浪商人，牛羊等）交互，比如与村民交易，喂食动物。
5. AI玩家可以与门，按钮等进行交互。
6. (*)加入Carry on模组之后，AI玩家还可以抱起由服务端配置文件所规定的可以抱起的实体或箱子。
7. (*)加入机械动力模组及其附属后，AI玩家还应该能够和机械动力及附属的机械交互。
#### 游戏环境感知
1. AI玩家能够获取服务器聊天列表，使用指令和发送信息
2. AI玩家能够知道他周围及面前的方块（及状态）是什么？可以参考MineFlyer的做法。
3. AI玩家能够知道服务器实体的类型及位置，包括掉落物，友好和敌对生物，功能性实体。
4. AI玩家应该能够正确识别附近的方块及实体的碰撞箱和交互体积。
5. AI玩家能感知时间

#### MCP基本要求
1. MCP客户端（比如DSH插件）可以直接通过一些列的Tool Chain Call，无阻塞地进行游戏，这意味着每个Tool都必须根据实际设计一个timeout时间，并把及时把状态报告给MCP客户端。
2. 应当有相应文件来记录（记忆）上下文。
3. MCP客户端直接桥接到正在游戏中的有头客户端（比如启动的整合包）

#### 开发环境要求
1. NewForge 1.21.1 重度机械症整合包（游戏源代码可能被魔改，注意兼容所有意外情况）。
2. 标注(*)的需求不优先实现。
3. 工作目录位于本机D:/mc/Development
